⚠️ 쿠팡 "입점수수료 비싸다"의 정체 — 모델별 실질 부담 (CEO 지적 반영)

CEO가 말한 30%급 부담은 틀린 게 아니라 다른 모델 얘기다. 쿠팡은 파는 방식이 3가지고 실질 부담이 완전히 다르다:

모델부담 구조실질 부담 (2만원 하네스 기준)
판매자배송판매수수료 10.8%만, 배송은 셀러 직접10.8% + 자체 택배비
로켓그로스 (쿠팡 창고 위탁)10.8% + 입출고·배송요금(건당 정액, 사이즈·무게 6단계) + 보관비프로모션 약 21% / 정상가 약 30% (극소형 물류 건당 1,950~3,850원)
로켓배송 입점 (납품)쿠팡이 매입 — 공급가 협상으로 마진 확보약 40%+ (통용치 — 상품별 협상)
  • CEO 어림 "30%급"은 로켓그로스 정상가·로켓배송 기준으로 대체로 맞다. 판매자배송(10.8%) 기준으로만 과대 — 모델 구분이 핵심
  • 로켓그로스 프로모션 단가는 2027-01-31 종료 — 계산기 프리셋에 프로모션/정상가 토글 필수
  • ⚠️ 심화 필요: 극소형 vs 소형 커트라인 치수(건당 ~900원 차이) — 쿠팡 WING 요금표에서 하네스 실측 치수로 확정

→ 계산기는 %가 아니라 "% + 건당 정액" 구조의 모델별 프리셋으로 설계한다 (3장 스펙에 반영됨).

3. 판매가 계산기 스펙 (예나)

구조 원칙

  • 수수료·관세·환율은 코드에 안 박고 프리셋 데이터로 — 수치 바뀌면 프리셋만 교체
  • 과세유형 토글(일반/간이)이 수식을 가름 — 최상단 입력
  • 마진율 정의는 판매가 대비로 통일 (원가 대비와 혼용 금지, UI에 명시)
  • 마켓 프리셋은 % + 건당 정액 복합 구조 (로켓그로스 대응)

입력 → 출력

입력 (원가)입력 (판매)출력
도매가(CNY→자동 환산), 대행 수수료율, 국제운송(총액→개당 배분), 관세율(C/O 여부), 택배비, 포장재, 기타, 불량률마켓 프리셋(수수료% + 건당 정액), 광고비율, 목표 마진율 또는 판매가, 월 고정비, 초기 투자금권장 판매가(₩x,900 스냅), 개당 마진액·마진율, 손익분기 판매량(월 고정비 기준 + 투자금 회수 기준), 마켓별 비교 테이블

핵심 공식 (일반과세자 기준)

원가(landed) = 도매가 + 대행수수료 + 국제운송(개당) + 관세 + 포장재 + 택배비 + 기타  ×(1+불량률)
  · 수입 부가세는 매입공제로 돌려받으므로 원가 아님 (단, 현금은 나가니 초기 투자금엔 포함)

마진 = 공급가액(판매가÷1.1) − landed − 마켓수수료 − 건당정액(풀필먼트) − 광고비(순액)
역산 판매가 = landed ÷ (k − 목표마진율)   ← k = 수수료·광고 구조로 정해지는 계수
손익분기: 월 고정비 ÷ 개당마진 (월간) · 초기 투자금 ÷ 개당마진 (회수)
예시 계산 (가정치 — 실측 아님): 하네스 도매 $4(≈5,600원), 대행 8%, 국제운송 500원/개, C/O 있어 관세 0%, 포장 300원, 택배 3,000원 → landed ≈ 9,850원
판매가 39,000원(호지 에센셜 앵커), 광고비 10% 가정 시 —
· 스마트스토어(5.65%): 개당 마진 약 19,900원 (마진율 51%)
· 쿠팡 판매자배송(10.8%): 개당 마진 약 17,800원 (마진율 46%)
→ 300개 사입(투자 약 300만원) 기준 손익분기 약 150~170개. 구조가 나온다.

4. 재고 관리 장부 스펙 (예나 — 1인 운영 기준)

  • 시트 3장 구조: ① 상품 마스터(SKU: VW-HN-RD-M 식, 리오더 임계수량) ② 입고 기록(개당 원가 = 계산기 landed 자동 연동) ③ 출고 기록(일 단위 마감 — 건별 입력 금지, 하루 5분)
  • 자동 계산: 현재고 = Σ입고−Σ출고 / 평균원가 = 이동평균 / 재고자산 = 현재고×평균원가
  • 주 1회 실물 카운트 대조, 현재고 ≤ 임계치 → 재발주 알림
  • 과설계 방지 명시: 로트·바코드·API 자동수집·다중권한 전부 제외 (월 수백 건 전까지 불필요)

5. VUUI 전산 — Supabase + Vercel (CEO 확정 스택)

noroo-archive에서 검증한 Next.js+Supabase+Vercel 무료 티어 패턴 그대로 재사용. 인증은 Supabase Auth 1계정 + RLS(내 행만 접근) — URL이 새도 데이터는 안 열림. 스키마는 지금 전부 확정, 화면은 3단계 구현.

DB 기본 틀 — 테이블 8개

7. CEO 결정 필요 항목

  1. 사업자 명의 구조 — 동생 단독 대표 vs noroo 공동사업자 등록 (예나 권고: 공동사업자 — 명의대여 리스크 회피)
  2. 과세유형 — 일반과세자(수입 VAT 공제 가능, 신고 연 2회) vs 간이과세자(공제 불가, 신고 연 1회). 수입업은 매입 VAT가 커서 일반과세가 통상 유리 — 사업자등록 때 확정
  3. 쿠팡 진입 모델 — 판매자배송(수수료 낮음, 배송 직접) vs 로켓그로스(부담 크지만 로켓 배지) — 계산기 1단계 완성 후 숫자 보고 결정 권장
  4. 재무 에이전트 이름 컨펌 (예나 제안: 하은)

8. 다음 단계

  1. 이 기획서 승인 → 전산 1단계 착수: Supabase 프로젝트 생성(노루군 계정) + 8테이블 마이그레이션 + 계산기 화면 → Vercel 배포
  2. 노루군은 그동안 1688에서 제품 탐색 계속 — 후보 생기면 계산기에 도매가만 넣으면 마진 즉답
  3. 첫 발주 확정 → 2단계(재고), 판매 개시 → 3단계(정산·손익) + 재무 에이전트 가동
